# shadcn/ui with Vite (Tailwind v4) — current recommended setup (2026)

## Install (bun)

```bash
# 1. Create Vite project (React + TypeScript)
bun create vite@latest my-app --template react-ts

# 2. Add Tailwind CSS v4 (Vite plugin — no tailwind.config needed)
bun add tailwindcss @tailwindcss/vite

# 3. Add path alias helper
bun add -D @types/node

# 4. Init shadcn/ui
bunx shadcn@latest init

# 5. Add components
bunx shadcn@latest add button card chart table
```

(Scaffold alternative: `bunx shadcn@latest init -t vite` creates the whole project.)

## Config files

### vite.config.ts

```ts
import path from "path"
import tailwindcss from "@tailwindcss/vite"
import react from "@vitejs/plugin-react"
import { defineConfig } from "vite"

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "./src"),
    },
  },
})
```

### tsconfig.json and tsconfig.app.json

Vite splits TS config — add `baseUrl` + `paths` to BOTH:

```jsonc
// tsconfig.json
{
  "files": [],
  "references": [
    { "path": "./tsconfig.app.json" },
    { "path": "./tsconfig.node.json" }
  ],
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}

// tsconfig.app.json
{
  "compilerOptions": {
    // ...existing...
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

### src/index.css (Tailwind v4 — completely different from v3)

```css
@import "tailwindcss";
```

That's it — NO `@tailwind base/components/utilities`, NO `tailwind.config.*` file. (shadcn's init writes the full theme scaffold with CSS variables — see below.)

### components.json (generated by init)

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/index.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide"
}
```

**Tailwind v4 gotcha: `tailwind.config` must be `""` (blank)** — there is no tailwind config file in v4.

## cn() utility (lib/utils.ts)

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

Deps: `clsx` + `tailwind-merge` (both installed by shadcn init).

## Theming: CSS variables + @theme (Tailwind v4)

shadcn uses **CSS variables** for theming (set `tailwind.cssVariables: true`). Components use semantic tokens: `<div className="bg-background text-foreground" />`.

Structure in `src/index.css`:

```css
@import "tailwindcss";
@import "shadcn/tailwind.css";          /* added by recent versions */

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-card: var(--card);
  /* ... --color-* for every token ... */
  --color-chart-1: var(--chart-1);
  /* ... chart-2..5, sidebar, etc. ... */
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: calc(var(--radius) * 0.8);
  --radius-lg: var(--radius);
  /* ... */
}

:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  /* ... all tokens as oklch values ... */
  --chart-1: oklch(0.646 0.222 41.116);
  /* ... */
}

.dark {
  /* overrides of the same tokens */
}
```

- `@theme inline` maps CSS vars → Tailwind color utilities (`bg-background`, `text-foreground`, `border-border`, `ring-ring`).
- Dark mode = overriding the same tokens inside `.dark` + the `@custom-variant dark` line.
- `--radius` drives a derived radius scale (`--radius-sm` … `--radius-4xl`).
- Custom tokens: define under `:root`/`.dark`, expose with `@theme inline { --color-warning: var(--warning); }`, then use `bg-warning`.
- Base colors available: Neutral, Stone, Zinc, Mauve, Olive, Mist, Taupe.

## Radix vs Base UI — is Radix still the base?

**Both exist in 2026:**
- `components.json` `"style": "new-york"` (default) → components are built on **Radix UI**, now imported from the unified **`radix-ui`** package (not per-package `@radix-ui/react-*`): `import { Select as SelectPrimitive } from "radix-ui"`. Also `class-variance-authority` for variants + `lucide-react` icons + `data-slot` attributes for styling.
- `"style": "base-nova"` (newer, optional) → components use **Base UI** (`@base-ui/react`) primitives instead of Radix (e.g. `import { Button as ButtonPrimitive } from "@base-ui/react/button"`).
- The `init` CLI now generates components that work with either style; `new-york` + `radix-ui` is the safe default for most projects.

## Version gotchas

- **Tailwind v4 vs v3**: no `tailwind.config.js`, no `@tailwind` directives, no `postcss.config` with autoprefixer. Use `@tailwindcss/vite` plugin and `@import "tailwindcss"`. Do NOT copy v3 setup guides.
- **components.json**: `tailwind.config: ""` in v4.
- **tsconfig**: alias must be in both `tsconfig.json` and `tsconfig.app.json` (editor resolution) + `vite.config.ts` (build resolution).
- New alternative to `@/` paths: `package.json` `"imports": { "#components/*": "./src/components/*.tsx", ... }` with `moduleResolution: "bundler"` + `resolvePackageJsonImports: true` — optional, `@/` alias remains standard.
- Charts: `bunx shadcn@latest add chart` — the shadcn Chart wrapper is built on Recharts and reuses `--chart-1..5` tokens.
